# 致富证券成交邮件自动入账 — 设计（2026-10-07）

## 背景

用户在致富证券（Chief Securities，donotreply@chiefgroup.com.hk）成交后会收到
「订单成交及部交及部分成交通知」邮件，需要与 HSBC 成交邮件同款处理：30 分钟
轮询拉取 → 解析 → `apply_trade` 幂等编排（先插 trade_records 再动 holdings/
cash_accounts）。实测样本（2026-10-07 卖出 03152）：

```
您卖出 #03152 (Ａ博时港元)的成交，详情如下：
参考编号 98438804 / 客户编号 M****27 / 货币 HKD / 价格 1135.100
已成交数量 1 / 待成交数量 0 / 成交金额 1135.100 / 最后更新时间 2026-10-07 10:57:44
```

## 决策（用户已确认）

1. **部分成交口径（HSBC 同款）**：`待成交数量 > 0` 的邮件跳过，只应用终态邮件
   （待成交=0），数量取该邮件「已成交数量」（视为订单累计终态）。
2. **现金动账**：优先取邮件「成交金额」（=数量×价格），费用差额走记账对账。
3. **部署即回溯补账**：上线后自动应用当天邮件（03152→0，HKD +1135.10）。

## 实现

- `parse_chief_trade(text)` 纯函数：门槛字段（您买入/卖出句式 + 参考编号 +
  已成交/待成交数量）齐备且待成交=0 才返回，否则 None（同发件人的营销邮件
  自然被挡）。symbol 取 `#` 后代码（03152 保留前导零 → market HK；字母数字
  → US），名称 NFKC 归一化（Ａ→A 与 holdings 现名一致），货币取「货币」字段
  （缺省按市场兜底），金额取「成交金额」（可缺省）。全文先 NFKC 简化全角容错。
- `fetch_chief_emails(days)`：与 `fetch_hsbc_emails` 同构，抽共享私有核心
  `_fetch_sender_emails(sender, days)`；只读、失败抛异常。
- `poll_once`：同一回溯窗口先 HSBC 后致富；任一源拉取失败不推进水位。
- `apply_trade`：接受可选 `amount`（缺省 qty×price，HSBC 行为不变）。
- 表结构零改动：致富参考编号纯数字与 HSBC P/S 前缀不冲突；仅更新
  trade_records DDL 注释（新建库时准确）。

## 测试

真实样本脱敏全字段断言、HTML 表格版式、部分成交跳过、营销邮件 None、
NFKC/千分位/货币缺省兜底、amount 透传扣现金、poll_once 双源失败水位语义。
