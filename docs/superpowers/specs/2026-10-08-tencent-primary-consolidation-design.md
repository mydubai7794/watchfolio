# 腾讯主源收敛与全局降频 设计文档（spec）

> 日期：2026-10-08
> 状态：已实施并上线验证（期指 4/5 腾讯主源、东财/新浪零请求、总线 10s 节拍；
> NK=fuNIY 顺手补齐存量缺失，DAX 三源均缺维持 null）
> 背景：N225/KS11 断供修复过程中发现 qt.gtimg.cn 覆盖远超预期（gz 全球指数 /
> fu 股指期货 / us·hk 指数汇率），且东财 push2、新浪 hq.sinajs 均对腾讯云
> 服务器 IP 风控。用户决策：主数据源尽可能收敛到腾讯，全局降频 30s 保源。

## 一、背景与目标

- 现状痛点：主源分散在东财（期指，12 次/分钟）、长桥（看板指数）、
  twelvedata（USDCNH）、Yahoo（美债）等多家，其中新浪/东财已被服务器 IP
  风控，期指实际处于「东财单点 + 新浪冷备失效」的裸奔状态。
- 目标：
  1. 凡腾讯有能力承载的主数据源，全部迁到 qt.gtimg.cn（经 tencent_bus
     攒批，与 A 股 ETF 同一次 HTTP，零额外请求）；
  2. 全局请求节拍降频到 30s，保护腾讯源不触发风控；
  3. 输出迁移后的「残留其他源清单」，明确每项保留原因。

## 二、已确认决策（用户拍板）

| 决策点 | 结论 |
|---|---|
| 迁移范围 | 期指迁腾讯（东财/新浪降兜底）；看板指数**不迁**（长桥是稳定源，不动） |
| 全局节拍 | 10s（总线 min_interval 与监控/候选循环节拍同步放宽到 10s） |
| 主源策略 | 腾讯能获取的数据一律腾讯主源；东财/新浪仅在腾讯无法获取时兜底（封禁严厉度：东财 > 新浪 = 雅虎，腾讯基本不封） |
| 残留源 | 迁移后输出清单，逐项标注原因（§五） |

## 四、迁移方案

### 4.1 期指（fetcher.py）

- 新增 `_TENCENT_FUTURES_MAP = {"NQ": "fuNQ", "ES": "fuES", "YM": "fuYM"}`。
- `_fetch_futures_tencent(futures_indices)`：`tencent_bus.get(fu codes)`，
  解析 f[3]/f[31]/f[32]，返回 {NQ: change_pct, ...} 与现有出参同构。
- 路由反转：`fetch_futures_with_routing` 主路径改为腾讯（bus 搭批），
  失败降级现有链（东财 futsseapi → 新浪 hf_）；健康状态机复用。
- 东财期指请求量：A股时段 12 次/分钟 → 0（仅腾讯失败时触发）。
- 新浪期指路径的全球指数顺带解析（b_NKY）继续保留为深兜底。

### 4.2 看板指数（明确不迁，用户拍板）

- 长桥是稳定源，VIX/DJI/NDX/SPX 主价链维持现状（长桥批量 60s +
  Yahoo 兜底），腾讯 usDJI/usNDX/usINX 留作能力备查（§3.1）不做实施。

### 4.3 全球指数（fetcher.py，已上线部分微调）

- N225/KS11 走 gz 总线搭批（60s 节流）维持现状。
- 可选项：gzFTSE 纳入候选池（candidate_pool 加行 + 映射一行），默认不做，
  用户点名再做。

### 4.4 降频 10s（config.py + tencent_bus.py + server.py）

| 参数 | 现值 | 新值 | 说明 |
|---|---|---|---|
| TencentBus.min_interval | 3.0s | 10.0s | 总线真实拉取节拍（config 引入 `TENCENT_BUS_INTERVAL_SEC`） |
| TencentBus.ttl | 4.0s | 不变 | 10s 节拍下每批必真拉，TTL 语义不受影响 |
| 监控循环驱动 | 3~5s | 10s | 与总线节拍对齐（MIN_INTERVAL_SEC 是代理轮转限速语义，不动） |
| 候选轮 A股时段（CANDIDATE_REFRESH_SEC） | 5s | 10s | 与总线节拍对齐 |
| 候选轮窗口外 | 60s | 60s（不变） | 本就 ≥10s |
| 持仓轮盘中 | 10s | 10s（不变） | 夜盘 60s 不变 |
| 全球指数节流 | 60s | 60s（不变） | 已达标 |

请求量收敛（A股时段，对 qt.gtimg.cn）：
- 现状：总线 ~12 次/分钟（3s 节拍）+ 东财期指 12 次/分钟 = ~24 次/分钟
- 迁移后：总线 6 次/分钟（10s 节拍，全部品种同一批）+ 东财 0 = **6 次/分钟**

## 六、风险与权衡（需用户知悉）

1. **监控时效 5s → 30s**：竞价套利窗口（09:15-09:25）与决策模型的数据
   粒度变粗，盘中异动告警最多延迟 30s。这是「保腾讯源」的直接代价，
   用户已拍板接受；节拍收敛为 config 常量，如需临时提速改一处即可。
2. **单源集中度上升**：A 股/美股/港股/期指/看板指数/全球指数全在
   qt.gtimg.cn 一家。缓解：该域名直连多年零风控记录；东财 futsseapi
   （不同域）冷备可接管期指；indexRankDetail2/worldCommodities 备查
   通道可手动切换。
3. **fu 前缀 delay 标记**：当前实测实时，若腾讯切真延迟由东财冷备接管
   （§3.2 注）。
4. **gzFTSE 覆盖不齐**（gzDAX 无）：全球指数扩展时逐个实测。

## 七、验证计划

1. 单测：fu 解析（真实样本行）、路由反转降级链、bus 30s 节拍参数；
   基线 401+ 用例全绿。
2. 部署后线上验证：
   - `/api/quote` 期指/指数值与 qt.gtimg.cn 直连值一致；
   - journalctl 确认「东方财富期指」日志归零、总线拉取间隔 ≥30s；
   - market_ticks 中 DJI/NDX/SPX 腾讯主价持续写入、spark 正常；
   - 监控页/持仓页/看板三端人工回归。
3. 请求量复核：`journalctl | grep -c 总线` 按分钟计数 ≈ 2。

## 八、明确不做

- VIX / 美债 / USDCNH / 扩展价 / 基金 NAV 迁移（腾讯无能力，§3.2）；
- gzFTSE 新增候选（可选项，等点名）；
- 腾讯日K替代长桥锚点（低频后台任务，收益小，另行评估）；
- Yahoo/twelvedata/长桥的兜底链结构调整（只调优先序不动结构）。
