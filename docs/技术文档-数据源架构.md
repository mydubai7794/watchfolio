# 技术文档：数据源架构（请求 / 退避 / 轮换 / 兜底）

> 项目：qdii 持仓网站（美股 + 港股 + 基金 + 现金，USD 口径）
> 核心原则：**少请求、多数据、回显/折线全用数据库**——一切对外请求都是稀缺资源，
> 能落库的不重复拉，能算的不查，能定格的不猜。

## 2. 会话状态机（请求频次的总开关）

`server._portfolio_loop` 每轮先由本地时间推演 session（不产生请求）：

| session | 判定 | 轮询间隔 | 行为 |
|---------|------|---------|------|
| regular | 周一~五 09:30-16:00 ET | 10s | 腾讯/新浪实时，tick 全落库 |
| pre | 04:00-09:30 ET | 30s | 真实盘前价（腾讯 ext）优先，24h价兜底（§3） |
| post | 16:00-20:00 ET | 30s | 真实盘后价（腾讯 ext）优先，24h价兜底（§3） |
| closed（夜盘 20:00-次日 04:00 / 周末 / 假日） | — | 60s | **24h数据源代理价直接覆盖**（§3） |

tick 落库条件：`session != "closed"` 或 `overnight_used > 0`——24h窗口全段有
活价即写 tick（24h 曲线连续），纯定格态不写避免灌库（少请求、少写入原则）。

状态机必须先于夜盘覆盖执行（回归修复 dcd1670）：覆盖只改展示价 `q["price"]`，
不回写定格的 `close_prices`，否则周末收盘价会被代理价污染。

**冷启动锚点恢复**：重启落在非 regular 时段时，腾讯昨收(f[4])语义已切换为最近
收盘，直接退化会让 base==close → close_pnl 恒 0（$0.00 问题根因）。恢复路径：
twelvedata quote 批量拉当日 open/close（8 只/批、60s 节流渐进），base=open、
close=close；`base_restored` 集合区分真锚点与退化值，连续失败 3 次放弃
（退化兜底，09:30 开盘自愈）。

**涨跌幅三层展示口径**（前端持仓明细）：
- 盘中（regular）：`live_change_pct`（场基准→现价实时累计）；
- 收盘后（仅美股行）：`day_close_pct`（场基准→16:00 收盘定格，即今日盈亏
  定格版）+ 夜盘徽标 `overnight_change_pct`（收盘定格→现价，实时）；
- 恒等式：day_close × (1+overnight) ≈ live（复合叠加），今日盈亏主数字恒用
  实时累计（day_pnl=close_pnl+overnight_pnl）。港股/基金不适用美股一场
  口径，恒用 live。

## 3. 24h数据源（收盘→开盘全段活价）

- **窗口** = `session != "regular"`（盘后 16-20 + 夜盘 20-4 + 盘前 4-9:30 +
  周末/假日全段）；pre/post 段腾讯/新浪真实扩展价优先，24h价兜底无盘口标的；
  closed 段直接覆盖。

- **映射规则**：美股代码 → `代码 + "B" + USDT` 精确匹配（AMD → AMDBUSDT），
  从 `/exchangeInfo` 取 `status=TRADING` 的交易符号构建，24h 缓存。
  当前覆盖 9/13 直连 + QQQM 经 `H24_ALIAS` 借 QQQ 涨跌幅推导（10/14；
  AMKR/PCG/F 无对应交易 → pre/post 段腾讯扩展价兜底，closed 段定格）。
- **取价口径**：`/ticker/bookTicker` 批量（symbols JSON 数组，weight 1）的
  `(bidPrice + askPrice) / 2` 中间价，与美股收盘偏差经验值 0.02%-0.1%
  （用户允许的近似误差）。
- **网络路径（实测结论）**：端点用官方公开行情镜像域名（境内服务器**直连可达**，
  ping/ticker/exchangeInfo 实测 200）。域名属接口契约不在文档展开；早期误判
  「必须境外代理」的根因是主站域名对机房 IP 段 TLS 封禁，换镜像域名后解除。
  请求顺序：直连优先，失败按代理候选逐个重试（最多前 2 个）。
- **代理分类机制**（直连失效时的保险）：`_h24_probe_loop` 每 30min 先探测
  直连，可用则代理无需分类；直连失败才逐个 GET `/ping`（weight 0）把可达代理
  标记 `region='overseas'`，夜盘请求优先走境外代理。
- **降级链**：直连 → 境外分类代理 → 通用代理池 → 返回 `{}` →
  `overnight_used=0` → 徽章「夜盘 · 数据定格」，价格定格 19:59 盘后价。

## 4. 数据源轮换与兜底矩阵

按「主源 → 次源 → 定格」设计，任一环节失败静默降级不抛错：

| 数据 | 主源 | 次源/兜底 | 最终态 |
|------|------|-----------|--------|
| 美股/港股现价 | 腾讯（批量） | — | 缺省（保留上轮价） |
| 期货/外汇 | 新浪 | 新浪失败→代理容错重试（`_get_text_resilient`） | 缺省 |
| 基金 NAV | FT | Yahoo v8 → twelvedata 批次 | NAV 缺省 |
| 夜盘美股价 | 24h数据源（境外代理） | — | 定格 19:59 价 |
| 美债/VIX 主价 | 新浪 hf | Yahoo 日线（range=5d 取最后 UTC 日，修早间缺口） | 缺省 |
| 港股日线 | 腾讯分时 | Yahoo daily | spark 缺省 |
| spark 折线 | 盘中：主价源同步写入 | 闭市：market_ticks 补拉（>30min 缺口触发） | 缺省 |

**twelvedata 批次轮换**（免费 8 credits/min）：`TWELVEDATA_BATCH = 8`，
多只需求按 `_td_cursor` 轮转分批；连续失败 ≥3 次（`_TD_FAIL_THRESHOLD`）熔断
60s（`_TD_MIN_INTERVAL_SEC`），避免无效 credits 消耗。

**Yahoo 补拉防放大**：闭市标的 spark 缺口补拉受三重限频——
缺口 >30min 才触发、成功后冷却 4h（`_BACKFILL_COOLDOWN_SEC = 14400`）、
失败后 5min 才重试（`_BACKFILL_RETRY_SEC = 300`）。

## 5. 指数退避与重试纪律

项目对退避的态度：**不做请求内自动退避放大，而是「轮次间隔天然退避 + 数据库兜底」**：

1. 单次请求失败不重试（除非有明确第二候选源），立即用数据库/上轮值回显；
2. 轮询循环按 session 间隔持续推进，源故障时自然形成 10s→30s→60s→600s 的
   间隔放大（随市场闭市）；twelvedata/补拉类有显式熔断窗口（§4）；
3. 代理候选遍历（最多前 2 个 + 直连重试一轮）是一次性尝试序列，不是循环退避；
4. 数据落库（market_ticks / trade_records / fund_nav）保证任何时刻前端都有
   上一份成功数据可回显——「宁可用旧数据，不发放大请求」。

## 6. 代理池分类（境外 / 通用）

- **存储**：`proxy_pool` 表，`region` 列分类——`overseas`（境外，24h数据源可用）/
  `unknown`（未分类）。存量库由启动迁移自动补列（查 `information_schema` 后
  `ALTER TABLE`，MySQL 不支持 `ADD COLUMN IF NOT EXISTS`）。
- **分类探测**：`server._h24_probe_loop` 每 30min 先探测 24h数据源直连——
  直连可用（当前生产常态）则跳过代理分类，省探测请求；直连失效才遍历存活代理，
  对 `unknown` 的逐个 GET `/ping`（weight 0 免 key），成功 → 标记 `overseas`；
  失败保持 `unknown`（可能只是抖动，下轮再测，不做永久否定标记）。首跑延迟 90s。
- **消费**：夜盘覆盖请求顺序 = 直连（`_h24_direct_ok=True` 时空候选）→
  境外分类代理（`db.get_overseas_proxies()`）→ 通用 `proxy_urls`。
  fetcher 内部按候选逐个尝试（直连 + 前 2 个代理）。
- **管理**：`/api/proxy` CRUD 手工维护代理池（免费代理源质量不稳定，人工供源）。

## 7. 落库与回显（一切折线来自数据库）

- `market_ticks`：统一 UTC 存储（HSI 腾讯分钟线 -8h 转换在 fetch 层完成），
  组合总值曲线、标的 spark 全部从 tick 重建，前端不直接消费外部行情；
- `fund_nav`：FT/Yahoo/twelvedata 三级来源都落同一张表，带 source 字段；
- `trade_records`：HSBC 邮件成交按 `message_id` 唯一键幂等入库，`trade_no`
  双重查重；SELL 校验持仓与可用数量；错误路径 = 人工修正，不做自动回滚；
- `proxy_pool`：代理可用性/分类/延迟全部落库，重启不丢分类成果。

## 8. 攒批发送路由（腾讯行情总线，tencent_bus.py）

qt.gtimg.cn 批量行情被四个消费方共用：A股监控（5s）/候选池（~10s）/持仓
（盘中 10s、闭市 60s）/看板混排（60s）。A股开盘（9:30-15:00 CST）恰逢美股
夜盘窗口（CST 08:00-16:00），原各自独立请求同域（实测 ~19 次/min）。

总线机制（微批合并）：
- **TTL 缓存**（4s）内的 code 直接回缓存；
- **发起条件**：距上次拉取 ≥3s（MIN_INTERVAL）的 get() 立即发起一次批量
  拉取，聚合全部待查 code（一个 URL，任意多 code）；
- **在飞共享**：冷却期内并发到达的 get() 共享同一次在飞请求，其新 code 记入
  pending 下一批带上；
- **失败不放大**：单次拉取失败消费方拿缓存旧值，失败 code 不无限催批。

效果：请求次数收敛为最高频循环节奏（~12 次/min，-37%），候选池/持仓/看板
零额外请求；监控闭市时自然降级为候选池节奏驱动。

24h数据源同理：`/api/v3/ticker/bookTicker?symbols=[...]`（URL 编码
JSON 数组，≤20 只 weight 仅 1）一次拿全部标的 bid/ask，替代逐只请求
（原 15 只=30 weight/轮 → 现 1 weight/轮）。

## 9. 数据源充足性 / 稳定性 / 替代源评估（2026-10-02 实测）

| 源 | 充足性 | 稳定性（实测） | 替代源/备注 |
|----|--------|----------------|-------------|

结论：当前矩阵**充足**。三个薄弱点及对策：

3. twelvedata 8 credits/min → 兜底与锚点恢复共用 60s 节流，批量 8 只轮换。
