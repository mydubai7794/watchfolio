## 一、系统概览

本系统是一个**券商风格的个人持仓管理网站**，域名 `<your-domain>`，部署于腾讯云服务器，由系统服务托管、开机自启。

- **覆盖四类资产**：美股、港股、场外基金、现金，全部统一折算为**美元口径**展示，另配一条**人民币口径**的累计盈亏；
- **附带两个子系统**：A股 QDII ETF 竞价监控（4 步决策模型）、记账报表（汇率/通道成本/盈亏恒等式）；
- **技术形态**：三个页面（持仓主页、监控页、记账页）加一个登录页，后端为一个 Python 服务加一个 MySQL 数据库（15 张表），无前端构建、无第三方中间件，全部自研单机运行；
- **核心设计原则**：少请求、多数据——能批量绝不逐只、能缓存绝不重查、页面看到的一切曲线全部从数据库重建，前端从不直接消费外部行情。

## 二、页面板块与功能

### 2.1 持仓主页（portfolio）

**账户总览条（页面顶部五格）**

| 板块 | 内容 |
|---|---|
| 总资产（美元） | 持仓市值 + 现金，附「昨收」基准小字 |
| 今日盈亏 | 实时累计；副行显示「收盘定格」与「昨收以来」徽标 |
| 持仓盈亏 | 相对成本的总浮盈亏 |
| 现金（美元） | 现金部分 |
| 人民币累计（CNY） | 总资产 × 美元人民币汇率 − 总投入 84,850 元，实时重算 |

**市场看板（11 张指标卡，带迷你走势图，可切换 当日/24小时/1月/3月/全部）**

纳指100、标普500、费城半导体、恒生指数、布伦特原油、COMEX黄金、美元指数、美债30Y、美债10Y、恐慌指数、美元人民币

**资产走势**：账户总值的分时/历史曲线（当日/24小时/1月/3月/全部）。

**分析看板**：资产构成（饼图）、持仓收益率、当日贡献。

**持仓明细表**：名称/代码、市场、币种、启用状态、数量、成本价、现价、市值（美元）、涨跌幅、今日盈亏、持仓盈亏、盈亏比例，支持点击表头排序。

**状态徽章**：页面顶部按美东时段显示 盘前/盘中/盘后/夜盘/闭市；夜盘若行情暂不可用会提示「价格定格于盘后收盘」。

### 2.2 监控页（QDII ETF 竞价监控）

对一批跨境 ETF 做开盘竞价监控，核心是 **4 步决策模型**，输出「买入/放弃」建议与推荐买入价：

1. **期指修正**——取纳指/标普期指涨跌幅，按系数放大修正（夜盘传导）；
2. **宏观情景分类**——确定剧本：**A 期指大跌破位**、**B 日内反转**（纳指跌但期指回升）、**C 常规震荡/上涨**，按剧本筛选候选；
3. **盘口否决**——买卖比低于阈值（默认 2.0）的一票否决；
4. **评分排序**——综合溢价率、买卖比、量能等加权评分，给出目标标的、决策与理由。

每只 ETF 展示：现价、参考净值（IOPV）、溢价率、买卖比、量能、评分、推荐买入价。

### 2.3 记账页（ledger）

| 板块 | 内容 |
|---|---|
| 投入与成本汇总 | 总投入 84,850 元（全额口径）、消耗（佣金/通道费） |
| 净盈亏（人民币） | 恒等式：**净盈亏 = 总资产×美元人民币汇率 − 总投入 = 增值 + 汇损 − 消耗** |
| 增值 / 汇损 | 分解展示 |
| 换汇通道成本 | 各通道点差对比 |
| 事件明细 | 换汇/出入金/交易事件流水（带参考号幂等，杜绝重复记账） |

## 三、核心口径：一场三层

美股「一场」= 美东开盘到下一次开盘。系统用**恒等式**保证任何时段盈亏可拆解、可对账：

> **今日盈亏（实时累计） = 收盘定格盈亏 + 夜盘增量**

- **基准** = 昨日收盘价（盘中时段每轮刷新；实测凌晨与盘前该字段均未切换，即天然是上一场基准）；
- **收盘定格** = 美东 16:00 收盘价定格（收盘后至次日盘前保持不变）；
- **夜盘增量** =（现价 − 收盘定格价）× 数量，夜盘徽标按涨跌着色；
- **冷启动保护**：服务重启若落在非盘中时段，用锚点恢复（见下）补昨日收盘价，恢复失败连续 3 次则放弃、次日开盘自愈，恢复值带「退化」标记防止与真实值混淆。

**状态机顺序（关键防污染设计）**：每轮必须**先**更新时段状态、**后**应用夜盘覆盖价——否则夜盘代理价会污染收盘定格价。

## 四、一天的数据流转（以美股一天为主线）

| 美东时段 | 系统行为 | 数据源 |
|---|---|---|
| 凌晨夜盘（04:00 前） | 收盘定格已固化；继续以 60 秒节奏刷新夜盘活价 | 24h数据源、长桥扩展价 |
| 盘前（04:00–09:30） | 30 秒一轮；优先用真实盘前扩展价，缺失时夜盘价兜底；「盘前计入上一场」 | 长桥/新浪扩展价、24h源 |
| 开盘（09:30） | 基准切换为当日凌晨刷新好的昨日收盘；锚点恢复若曾失败此时自愈 | 腾讯 |
| 盘中（09:30–16:00） | **10 秒一轮**，全速实时；24h源完全退出 | 腾讯（美股/港股混排批量） |
| 收盘（16:00） | 收盘价定格，写入当日最后一笔资产走势点 | 腾讯 |
| 盘后（16:00–20:00） | 30 秒一轮；真实盘后扩展价优先 | 长桥扩展价 |
| 夜盘（20:00–次日04:00） | 60 秒一轮；有 24h交易的标的用 24h价，同标的替代（如 QQM 借 QQQ 涨跌幅推导），3 只无交易的走股票行情网关；若整轮夜盘数据失效自动降为 600 秒慢轮，恢复后回到 60 秒 | 24h数据源、股票行情网关 |
| 周末/假日 | 全天按夜盘逻辑（60 秒），周六人民币汇率仍会小幅波动（离岸市场 7×24） | 同上 |

**服务重启时的锚点恢复**：重启后若发现持仓缺昨日收盘基准，启动一个后台任务**逐只**恢复（每只间隔 4 秒，13 只约一分钟摊完），主源为长桥日K，长桥不可用回切 twelvedata 批量——避免重启瞬间集中请求触发数据源风控。

## 五、后台任务一览

系统常驻 10 个后台循环，各司其职、节奏互不干扰：

| 任务 | 职责 | 节奏 |
|---|---|---|
| 持仓主循环 | 美股/港股/基金/现金行情与盈亏计算、时段状态机、夜盘覆盖 | 盘中 10 秒 / 盘前盘后 30 秒 / 夜盘 60 秒（数据失效时降 600 秒） |
| 市场看板循环 | 11 个看板指标主价与迷你走势数据 | 60 秒（其中新浪系 5 分钟节流） |
| ETF 监控循环 | A股竞价快照 + 4 步决策模型 | 约 5 秒一轮（仅交易时段），驱动腾讯攒批总线 |
| 候选池刷新 | 候选标的行情 | 按交易日程调度（盘中高频） |
| 基金净值循环 | 场外基金净值 | 60 秒（英国金融时报主源） |
| 邮件成交循环 | 拉取汇丰成交邮件、解析入库并**自动应用交易**（更新持仓数量与现金）；轮询水位失败不推进、按水位回溯，不丢邮件 | 30 分钟 |
| 记账汇率循环 | 欧洲央行人民币/港币/美元日线汇率 | 每日 22:35 一次（库空自动回填历史区间） |
| 24h源探测循环 | 给代理池打标（境内/境外出口），供请求路由 | 30 分钟 |
| 锚点恢复任务 | 重启后补昨日收盘基准（后台一次性） | 触发式，每只间隔 4 秒 |
| 交易时段/每日调度 | 时段切换、每日例行任务对时 | 常驻 |

## 八、稳定性与安全设计

- **攒批总线**：监控/候选/持仓/看板四个模块的腾讯请求合并成一个节奏，对外表现为一个客户端；
- **数据库回显**：页面一切曲线从库重建，外部源抖动不影响页面连续性；
- **三级降级**：每个关键数据项都有 主源 → 备源 → 上一份落库值 的降级链；
- **幂等入库**：记账事件、成交记录均带唯一参考号，重复数据不重复入账；
- **登录与会话**：页面需登录，接口凭会话令牌鉴权；
- **诊断工具**：向服务进程发信号可随时转储全部后台任务栈，用于排查「卡死」类问题（此前已用其证伪过一次假卡死，实为慢轮）。

## 九、已知边界

1. 免费代理池 9 个全是境内中转，仅 1 个有境外出口；雅虎常态 403 依赖代理池补拉；
2. 新浪白天偶发 403（美元指数/美元人民币主价有备用源自动接管）；
3. twelvedata 免费额度 8 次/分钟，已在多处降为兜底位；
4. 美元人民币显示的是**离岸**价（7×24 交易、周末仍波动），与银行 App 的在岸价存在正常价差（数十个基点内），非数据错误；
5. 24h源夜盘若整轮失效，持仓轮自动降为 600 秒慢轮——页面数据 10 分钟不动属正常降级，恢复后自动回到 60 秒。

## 十、测试与部署

- **测试基线**：238 项单元测试全部通过（持仓口径、决策模型、鉴权、邮件解析、长桥并发防护）；
- **部署方式**：本地同步至服务器后重启系统服务（rsync 全量排除开发文件）；
- **线上验证**：服务状态 + 日志 + 带会话令牌的接口抽查（总值、人民币累计、三层恒等式数值核对）。
